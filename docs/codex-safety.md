# Protected Codex adapter

The v1 supported runtime is **Codex CLI 0.154.0 on macOS**, with `/usr/bin/sandbox-exec` (Seatbelt). Other platforms/versions fail closed. The offline provider-independent workflow remains available. This narrow version gate is intentional: feature names and configuration loading behavior must be re-audited before expanding it.

Implementation is in `packages/cli/src/codex.ts`. Controls were checked against installed `codex exec --help`, `codex features list`, and the [official non-interactive CLI reference](https://learn.chatgpt.com/docs/developer-commands?surface=cli). The runtime documents `--ignore-user-config` and `--ignore-rules`; authentication is separate from configuration. [The configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference) describes integration and permission controls. Margin explicitly supplies them; prompting alone is never the write boundary.

## Process boundary

The trusted wrapper creates a mode-0700 OS temporary directory outside the project and a fresh HOME, CODEX_HOME, XDG config/data home, and work directory. It clears the inherited environment, including Node options, proxy overrides, Codex settings, and tool credentials. Only a small runtime environment is installed. OpenSSL configuration is set to `/dev/null` to avoid arbitrary host configuration. The npm Codex launcher is resolved to its installed native binary on macOS.

**Seatbelt wraps the entire Codex process**, including any descendants. It denies all filesystem writes outside this temporary directory, denies reads outside selected OS/runtime resources and the temporary directory, explicitly denies project reads, and restricts process execution to the resolved runtime binaries and a no-op probe. It also denies Apple events. No project directory is passed to the model process. The only author text supplied is the frozen packet on stdin. The wrapper reads final output and writes validated review sidecars after the child exits.

OS/runtime read allowances include macOS system resources, Homebrew libraries, the executable, `/dev`, and the filesystem root directory entry. These are trusted runtime dependencies, not review context. The author's explicit project directory is denied even if it sits beneath an allowed system location. This boundary assumes a trusted installed Codex/Node runtime and OS, not a malicious executable or OS compromise. Network access remains available to Codex's model transport; this is not a hostname firewall or a promise about the provider's retention policy. No network-capable model integrations are configured or enabled.

## Codex controls

The invocation uses non-interactive `exec`, `--sandbox read-only`, `approval_policy="never"`, `approvals_reviewer="user"`, `--strict-config`, `--ignore-user-config`, `--ignore-rules`, `--ephemeral`, stdin input, `--output-schema`, and `--output-last-message`. No full-auto, workspace-write, bypass, or permission-escalation flags are accepted.

Hooks, MCP definitions, app defaults, plugins/catalogs, shell-tool exposure, shell snapshots, agents, browsers/computer use, image tools, skill discovery/install, memories, automatic goals, and approval helpers are disabled. **0.154.0 forces its `unified_exec` backend on even with a false config value.** Margin does not claim to disable that backend: it verifies `shell_tool=false` and uses the outer OS process-execution/read/write restrictions as the boundary. This behavior was checked against the installed runtime. Project instruction loading is disabled. Empty MCP/hook settings and fresh directories prevent inheritance of user/project integrations, plugins, hooks, and rules. Managed host configuration is not supported and cannot be read from its ordinary locations under the outer read restriction. A config/runtime incompatibility fails the run rather than weakening protections.

Before credentials or model execution, the wrapper runs bounded version/help/feature checks inside Seatbelt. It checks the exact version and required flags, then verifies that each configured feature disable actually took effect. In 0.154.0 `features list` rejects `--strict-config`; that probe omits only this flag, while actual `exec` requires it. The final response schema is always generated from the frozen request. The wrapper reads lifecycle events from the [documented JSONL stream](https://learn.chatgpt.com/docs/non-interactive-mode), using `exec --json` alongside `--output-last-message`. Only fixed progress descriptions are displayed; reasoning and response bodies are omitted. Diagnostic classes from structured errors or stderr survive timeout reporting. Progress events are never used as the final response; the final file still passes all importer checks.

## Authentication, failures, and limits

Existing file-backed `CODEX_HOME/auth.json` (otherwise `~/.codex/auth.json`) is copied into the private temporary home, without printing or storing it in `.reviews`. Alternatively, an existing `OPENAI_API_KEY` is written into the isolated auth file. The wrapper never reads config, MCP token stores, plugins, or history. Keychain-only login, custom model endpoints, proxy-based setups, managed policies, and write-capable integrations are unsupported. Temporary credentials are removed on normal completion, error, cancellation, and timeout. A machine crash or forced kill of Margin itself may leave `margin-codex-*` OS temp directories; treat them as sensitive and remove them yourself when no reviewer is running. Authentication refreshes in the isolated copy are not written back to your normal login.

Provider subprocesses use argument arrays, no shell, a separate process group, a 120-second model timeout, five-second probes, a 2 MiB combined progress-output bound, and a 1 MiB final-response bound. Cancellation kills the process group. Final output must be a regular non-symlink file in the wrapper's temp directory. Missing executable/authentication, unsupported controls, malformed output, and provider failures retain the prepared request for manual import. Failure diagnostics avoid persisting provider logs that might contain runtime secrets.

Connection diagnostics distinguish recognized DNS, TLS/certificate, proxy, refused/reset connection, WebSocket, timeout, rate-limit, and server errors using fixed descriptions. URL contents are excluded from classification. Model-catalog errors are labeled when identifiable: a catalog warning before `thread.started` does not prove the later review failed. Raw Codex stderr is omitted from exit errors as well as progress. Unknown errors remain unknown; Margin never fabricates an underlying cause.

`margin doctor` runs without model credentials or a review request. A trusted, fixed Node program sends unauthenticated HTTPS HEAD requests to two fixed hostnames (`chatgpt.com`, `api.openai.com`), with normal certificate verification, no redirects, no body processing, and an eight-second deadline. It runs inside the same outer Seatbelt profile and separately as a control outside Seatbelt; both use the exact cleared review environment. The control is this fixed networking program, never Codex or source content. Subprocesses are limited to ten seconds and 16 KiB of output; macOS/Codex version probes use five-second limits. Results contain only versions, predefined hostnames, network phase, HTTP status or allowlisted error code, and names of omitted environment overrides. It never reads authentication or project files, or writes `.reviews`. Temporary directories are removed after success, failure, or cancellation.

These probes use Node's TLS implementation, not Codex's Rust implementation, and do not exercise WebSocket streaming or account/model access. A successful control and failed protected Node probe identifies a difference for Node, not a diagnosis of the model timeout. The [official environment-variable reference](https://learn.chatgpt.com/docs/config-file/environment-variables) and [authentication documentation](https://learn.chatgpt.com/docs/auth) describe custom CA bundles and environment authentication available to ordinary Codex; Margin intentionally does not inherit those overrides. Proxy/custom-CA support must be audited before enabling it.

Automated tests use fake executables and actual macOS Seatbelt to check attempted author-file reads/writes, arguments, configuration isolation, failures, output limits, cancellation, and importer validation. These are **not live model tests**. A separate live smoke on 2026-09-11 completed the bundled Markdown review in 18 seconds with an editorial letter and four valid comments; source hashes remained unchanged. This single result does not establish typical latency or compatibility with every account/network. Manual execution of another external agent with the packet is outside Margin's write-protection guarantee; the Margin importer itself still never edits drafts.
